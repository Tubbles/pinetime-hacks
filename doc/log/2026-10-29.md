# Log — 2026-10-29

## [phone][hub] 2026-10-29 — Home Assistant nudges Hub T every 5 minutes near the end of a print

- Ask: from 85 % progress or 30 minutes before the end, whichever comes first, a nudge every 5 minutes. Built in homelab PR #120 (commit `ceb21d6`, automation `hub_t_print_end_nudge`), spec in homelab `doc/work/hub-t-print-nudge.md`.
- Home Assistant reads `display_status.progress` and `print_stats.print_duration` from Moonraker's HTTP API, and only while printing: a `rest_command` with `response_variable`, which in 2026.9.4 returns the parsed JSON under `content` and raises a `HomeAssistantError` on a timeout or connection error (`rest_command/__init__.py`). Rejected: adding `print_duration` to Moonraker's MQTT `status_objects`, which would publish it every 5 s for the whole print into the recorder, and change fluiddpi too.
- Tradeoff, from the FCM docs (firebase.google.com/docs/cloud-messaging/android/message-priority): an app instance whose high-priority messages show no notification may get them deprioritized to normal priority, judged over 7 days per instance. Every nudge that goes through FCM is such a message for the companion app (Home Assistant uses FCM only while the app's websocket is down, `mobile_app/notify.py`), which also carries the visible print and backup notifications, so those could arrive late in Doze if FCM decides so. Watch for late notifications after the merge.
