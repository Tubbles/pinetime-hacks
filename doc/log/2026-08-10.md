# Log — 2026-08-10

## [infinitime] 2026-08-10 — disconnect buzz gated on the notifications-On mode

- User ask: no disconnect buzz in silent or sleep mode. InfiniTime's name for these is the `Settings::Notification` enum — `On`, `Off` (the quick-settings bell, "silent"), `Sleep` (the moon); there is no "normal mode", the plain state is just notifications On.
- The gate sits in SystemTask's `Messages::BleDisconnected` case, not in DisplayApp's handler: SystemTask already owns the identical policy check for the notification chime (`OnNewNotification`, `SystemTask.cpp:234`), and gating before the forward keeps DisplayApp's handler a pure buzz action.
- The buzz still fires with the screen off (that was deliberate in the original design, `a7e348a1`) — the gate is about the user-selected mode, not the display state.

## [infinitime] 2026-08-10 — disconnect buzz debounced: 1 s activation, 5 s re-arm

- User ask: no immediate buzz — 1 s activation delay, and a 5 s cooldown after reconnect before the buzz re-arms. Mechanism: a one-shot FreeRTOS timer in SystemTask (`bleDisconnectBuzzTimer`, mirrors the `measureBatteryTimer` callback-pushes-a-message pattern) plus a `lastBleConnectedTick` stamp taken on every `BleConnected`.
- The re-arm needs no second timer: at disconnect time the connection's uptime is `now - lastBleConnectedTick`, and the buzz timer is only started when that is ≥ 5 s. This also closes a subtle hole: with only an expiry-time `IsConnected()` re-check, the sequence drop → reconnect at 0.5 s → drop again at 0.8 s would buzz from the FIRST timer even though the second drop happened inside the cooldown. Because the second drop never starts the timer (uptime 0.3 s) and the reconnect at 0.5 s stopped the first one, it stays silent.
- Both guards are needed at expiry: `xTimerStop` on reconnect covers the normal cancel, and the `IsConnected()` re-check covers the race where the timer callback queued the expiry message just before the reconnect message was processed.
- The notification-mode gate (previous entry) moved with the forward: it is now evaluated at expiry time, not at disconnect time.
- Tick wraparound (49 days at 1024 Hz) is harmless: unsigned tick subtraction is wrap-safe for spans shorter than the wrap period.

## [infinitime] 2026-08-10 — G7710 glitched digits diagnosed: the trace buffers starved the heap

- Field report: after flashing `226c8eed`, the G7710 face's numbers rendered blank or as glitchy vertical lines, and with the face active for a while other labels went black too. Root cause chain, each link verified in source or the linker map:
  - InfiniTime's FreeRTOS heap is NOT a fixed array: `heap_4_infinitime.c` sizes it as `__StackLimit - __HeapLimit`, i.e. all RAM left after static data. Every new static byte is a heap byte lost.
  - The trace commit added `ring` + `snapshotBuffer` = 2 × 3,072 B of BSS (confirmed in `pinetime-app-1.16.1.map`), shrinking the heap from ~39.6 KiB to ~33.6 KiB.
  - `LV_MEM_CUSTOM = 1`: ALL LVGL allocations go through `pvPortMalloc`, so LVGL objects, task stacks, and runtime font loads share that one pool.
  - The G7710 is the only stock face that `lv_font_load`s fonts from the FS into the heap at create time (~9 KiB across three fonts: 7segments_115 4,928 B + dots_40 1,840 B + 7segments_40 760 B, plus per-alloc overhead; the 115 px glyph bitmap is a single ~4.5 KiB contiguous alloc).
  - LVGL 7's `lv_font_loader.c` checked NONE of its ten `lv_mem_alloc` calls: a failed glyph-bitmap alloc left `glyph_bitmap = NULL` and kept going, so rendering read garbage at NULL + offset (the vertical lines) or found no glyph (blank). Continued running on an exhausted heap then failed other labels' updates (the black fonts). Not persistent corruption: FS and resources were never touched.
- Fixes, four commits: trace slimmed to a 64-record ring with freeze-on-readout, static cost 6,144 → 768 B (InfiniTime `de7296ae`); NULL checks on all ten loader allocations, in a new nested-fork submodule github.com/Tubbles/lvgl branch `font-loader-null-checks` (lvgl `bf87aaee`, submodule bump `898f16c8`); G7710 falls back to built-in fonts when a load fails, with destructor guards so `lv_font_free` never touches the built-ins (`9bbaa58d`).
- Standing lesson for ALL future firmware work: static buffers are not free on this platform — the heap absorbs every byte. Budget them, and check the map (`__HeapLimit`) when adding any.
- The freeze-readout trade-off: recording drops events while a snapshot is being paged out. Acceptable for a manually-driven diagnostic; recording resumes when the read drains.

## [infinitime] 2026-08-10 — Analog 12 second cut, from field feedback

- Hands: the stock Analog builds each hand from a thin inner `_trace` line plus a thick outer body; user wants uniformly thin, so one width-3 line from radius 5 to the tip, trace objects and styles dropped.
- Tick gap mystery solved: the stock Analog's linemeters deliberately span 300° with `angle_offset 180`, leaving the 60° gap at the TOP — under that face's lone "12" label. Copying them into a face with numerals everywhere left the 11-to-1 minute ticks missing. Fix: 360° scale with one extra line (61 minor / 13 major) — lv_linemeter spaces lines as `scale_angle / (line_cnt - 1)`, so first and last coincide at a full circle, and the derived start angle (270°) keeps every tick on a multiple of 6°.
- Numeral overlap, quantified: linemeter lines run inward from radius 120 by `scale_width` (major: to ~114). At NumeralRadius 100, the corners of the two-digit numerals reach ~114 from center ("11" worst). Radius 86 clears them by ~10 px; the minute hand (length 90) now crosses numerals, drawn on top like a real watch hand.
- Padlock indicator: this face has no heart-rate slot to borrow (the G7710/Digital pattern), so it gets a dedicated top-mid label, blank while unlocked. Numeral 12 sits at y≈24–44 at radius 86, so the top-mid icon (y≈0–20) does not collide.
