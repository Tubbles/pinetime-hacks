## [infinitime] 2026-08-04 — lock indicator: padlock glyph sourced, Digital face covered

- The wrist-raise lock indicator now also lives on the Digital watch face, mirroring the G7710 pattern exactly (lock borrows the heart-rate slot, `Refresh()` must restore `heartBeat` on unlock because the ctor sets it once). Padlock paints white on Digital (that face's default text color) vs `color_text` on the G7710.
- A true padlock glyph is now in the symbol font: fa-lock U+F023 added to the FontAwesome range of `jetbrains_mono_bold_20` (`src/displayapp/fonts/fonts.json`) as `Symbols::lock` ("\xEF\x80\xA3"). Both faces now use it; `shieldAlt` was only ever a stand-in chosen because it was already in the font (2026-08-02 entry). Verified U+F023 maps to glyph `lock` in the bundled `FontAwesome5-Solid+Brands+Regular.woff` before wiring it (fontTools cmap read).
- Font-patch safety, checked before touching `fonts.json`: the two post-generation patches on `jetbrains_mono_bold_20.c` fix the '0' and 'M' bitmaps, which sit BEFORE the FontAwesome glyphs in the generated file (glyphs are emitted in codepoint order), so inserting U+F023 shifts nothing above their hunks. The zero patch is a normal-format diff with absolute line numbers — it would silently corrupt the file if lines above it ever shifted, so any future glyph below 0x30, or a JetBrains range change, must re-check both patches. Confirmed in practice: the font target regenerated, patched, and compiled in the build.
- Local-build gotcha on the 8 GiB laptop: the default `-j$(nproc)` firmware build OOM-killed the host (took pipewire and the session dbus with it, exit 137 at ~65%). The dead session bus then broke rootless podman entirely (`crun: sd-bus call: Interactive authentication required` on every run — crun asks systemd for a cgroup scope over the user bus). Two-part workaround that works with no bus: `--cgroups=disabled` on `podman run`, and `-e OMP_NUM_THREADS=2` to cap parallelism (GNU `nproc` honors `OMP_NUM_THREADS`, and `build.sh` does `-j$(nproc)`). `--cpuset-cpus` does NOT work for this — it needs the same dead sd-bus call. Side effect to remember: recovering podman needed `podman system migrate`, which stopped the unrelated running `nginx-proxy-manager_db_1` container (restart blocked by the permission classifier; flagged to the user).
