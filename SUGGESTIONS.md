# Suggestions (not yet To Dos)

Everything below was noticed during work and written down so it isn't lost. These are optional ideas and observations — candidate To Dos, not committed work. Nothing here is planned or promised; an item only becomes an actual To Do when deliberately promoted into `TODO.md`.

- True padlock glyph for the wrist-raise lock indicator: v1 reuses `Symbols::shieldAlt` (U+F3ED, already in `jetbrains_mono_bold_20`); a real padlock means adding U+F023 to the FontAwesome range in `InfiniTime/src/displayapp/fonts/fonts.json` and regenerating with `fonts/generate.py`. Optional polish, deferred to keep v1 font-neutral.
- Watch timer could adopt the remaining duration of a phone-side paused timer: today a paused phone timer arrives as ClockSync "stopped" with `value_ms` = remaining, and the firmware only calls `StopTimer()`, discarding `value_ms`. Presetting the Timer screen's counters from it would make resume-on-watch seamless. Noticed during the 2026-08-02 review; deferred as beyond the review's contract.
- Latin Extended-A for notifications: JetBrains Mono Bold also covers 0x100-0x131 (and fc-query shows more beyond), so Polish/Czech/Turkish letters could join the Latin-1 block added for Swedish by extending the `jetbrains_mono_bold_20` range in `InfiniTime/src/displayapp/fonts/fonts.json` further (~30 B of flash per glyph). Deferred: the ask was Swedish, and each block should be weighed against the 474 KB flash budget (81.87% used after Latin-1).
- A small settings UI in the Clock fork for the clocksync prefs (`clocksync_watch_mac`, `clocksync_gadgetbridge_package`, `clocksync_dialer_package`): today they are BuildConfig-seeded/hand-set (`phone/clocksync/README.md` section c.3). Noticed while adding the third pref for the dialer package.
- Show the caller (name/number) on the InCall screen: Gadgetbridge T currently writes only a 1-byte active/ended flag to `00080002`; a richer frame (or reusing the incoming-call alert text) could carry the caller into the InCall title. Noticed while implementing call-state forwarding; deferred to keep the frame trivial.
- Upstream InfiniTime PR candidates from the 2026-08-03 DFU forensics (`doc/LOG.md`): the PersistBond stack-overflow fix trio (static buffers in `NimbleController.cpp`, host task stack size in `nimble_port_freertos.c`, `configCHECK_FOR_STACK_OVERFLOW 2`); the PersistBond CCCD read `idx = peer_count` bug; the MusicService duplicate `characteristicDefinition[6]`/`[7]` both registering `msTotalLengthCharUuid` (kept locally for stock-handle compatibility); and the Service Changed announcement after firmware updates. All are upstream-relevant, none are specific to this fork.
- Upstream Gadgetbridge PR candidate: the multi-target BLE Intent API (`c288c7894` in the GB T fork) — the package filter as a comma-separated list with per-package explicit broadcasts. Generic, removes the forwarding-hub workaround for any multi-consumer setup; empty setting preserves upstream behavior.
- Lock indicator beyond the watch faces and the Timer: any app can be raise-woken into, and outside those four screens a locked watch just ignores taps with no visible reason. A single `lv_label` painted by `DisplayApp` over whatever screen is loaded (rather than per screen) would cover all of them at once. Noticed while adding the Timer padlock on 2026-09-14; deferred because the Timer is the case that actually happens.
- Raise-wake window and settle can overlap at small windows: the clamp is `settle < window` as specified, so window 3 with settle 2 makes the "prev" and "now" groups share a sample and shrinks the measured roll. Harmless, but a `settle * 2 <= window` clamp would keep the two groups disjoint at every setting. Noticed while implementing the sliders on 2026-09-14.
- Raise wrist and Lower wrist pages show raw numbers (`Level 384`) with no live feedback, unlike Shake Calib. which animates the current speed against the threshold. A live readout of the current `xMean`/`yMean`/variance next to each slider would turn tuning from guesswork into a measurement. Noticed while building the pages.
- "Intercom" as a choice for Settings -> Default tab: the tab is always last and reachable in one swipe, so this was left out; a default-tab option would need a case in `MainActivity.getDefaultTab()`. Noticed while implementing the mode on 2026-09-14.
- Re-post the armed auto-open notification after a reboot: it is an ordinary ongoing notification, so a reboot clears it until the next state change or tab visit. A `BOOT_COMPLETED` receiver calling `IntercomAutoOpen.refreshSurfaces` would close that gap. Noticed while adding the notification on 2026-09-14.
- "Download watch log" in Gadgetbridge T: the watch now keeps `/events.log` (design: `doc/DESIGN-error-visibility.md`), and GB already speaks the BLE file-transfer protocol for uploads; a read path plus a menu entry would replace the laptop pull (`tools/pull_watch_file.py`). Noticed while adding the event log on 2026-09-17.
- Show which rule blocked a call in the call history: the log entry carries Android's blocked type but not the rule; the notification names it, the history cannot. A small pref map from call-log id to pattern, written when the block is decided, would let the recents row show it. Noticed while routing blocked calls into the call log on 2026-10-01.
- Per-slot write stamps in the Hub service: the generation counter is service-wide, so any accepted set (another source, or the phone's routine re-send of an unchanged event) repaints the corner once with identical content, and a wrap of the uint8 across exactly 256 sets during one sleep could keep a stale icon if the time did not change. A per-slot stamp (16 more bytes) removes both. Noticed in the 2026-10-27 review; below the bar for the printer, whose icon never changes.
- The recovery firmware target has not compiled since the key-tones service (`3b95e758`): `SystemTask.cpp` calls `displayApp.Register` with ClockSync, KeyTones, AlertNotification and now Hub pointers that `DisplayAppRecovery.h` has no overloads for, and nothing guards them with `PINETIME_IS_RECOVERY`. CI builds only `pinetime-mcuboot-app`, and the watch runs the bootloader's own recovery image, so nothing is affected until someone builds that target. Noticed in the 2026-10-27 review.
- Key Hub T's slicer-estimate cache by file size as well as name (`virtual_sdcard.file_size` comes in the same Moonraker query): today a re-sliced file uploaded under the same name is served the old estimate for the first 5 % of the print. Noticed in the 2026-10-27 review; PrusaSlicer's default names carry the print time, so same-name collisions are rare.
- Home Assistant arrival nudge for Hub T: the Wi-Fi join poll (`doc/DESIGN-hub.md`, "Scheduling") stays unarmed when the trip home starts on another Wi-Fi and is shorter than the poll interval, for example from work. The companion app's Wi-Fi connection sensor, if enabled on the phone, could send the same `POLL_NOW` command when it changes to the home network, which covers every route home. Noticed in the 2026-10-27 review.
- A status line for Hub T's Wi-Fi join poll: the nudge has its own "Last nudge" line, but a Wi-Fi join only shows up as a poll, so there is no direct way to see that the trigger fired. Noticed in the 2026-10-27 review.
- Another FluiddPI host on someone else's Wi-Fi: the images default to the hostname `fluiddpi`, so on a foreign network `fluiddpi.local:7125` could be a different printer and set or clear the corner. Checking the printer's identity before trusting a poll would rule it out. Noticed in the 2026-10-27 review, not verified, and true of the periodic poll since Hub T's start.
